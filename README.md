# docx-color-cli

A standalone CLI that converts tracked text changes in `.docx` files to *permanent font colors* without Microsoft Word, `python-docx`, or `docx-revisions`.

- Inserted text (`w:ins`, `w:moveTo`) → red (`FF0000`) and accepted.
- Unchanged text → black (`000000`).
- Deleted text (`w:del`, `w:moveFrom`) → removed.
- Accepts common formatting revisions while retaining current formatting, hyperlinks, field structures, tables and images where possible.
- Processes main body, headers, footers, footnotes, endnotes and comments XML.
- Leaves original input untouched; optional JSON summary.

## Install and run (uv)

```bash
uv sync
uv run docx-color manuscript.docx manuscript_colored.docx --report report.json
```

Or install with `pip install -e .` and run `docx-color input.docx output.docx`.

Custom colors: `--red 0000FF --black 000000`.

## Export directly as PDF

Requires **LibreOffice** installed and available as `libreoffice` or `soffice` on your PATH. On macOS, you can install LibreOffice from its official site or using `brew install --cask libreoffice`. The Python dependencies remain only `lxml`.

```bash
# Directly generate a PDF; no intermediate DOCX left on disk
uv run docx-color manuscript.docx manuscript_colored.pdf

# Or let the CLI choose the output name automatically
uv run docx-color manuscript.docx --format pdf

# Optional JSON report and blue insertions instead of red
uv run docx-color manuscript.docx manuscript_colored.pdf --red 0000FF --report report.json
```

PDF output is generated by first accepting/coloring revisions in a **temporary DOCX**, then rendering that document with LibreOffice. New text remains red by default; deleted text is absent. The source remains unchanged. For maximum layout fidelity, compare the PDF against a Word export, as LibreOffice may render certain fonts, fields, citations, or floating objects differently.

## Limitations

The converter focuses on *text revisions*. Complex structure changes, particularly tracked deletions of paragraph marks and tracked table row/cell edits, are **not fully supported**. By default, it raises an error instead of silently generating an incorrect document. `--no-strict` bypasses the error but requires careful manual review. Tracked field alterations, moves and nested changes can also require inspection. Reducing all original text to black intentionally replaces existing font colors.

Run tests with `uv run --extra dev pytest -q`.

Always compare the final document against a Word-rendered original, especially for citations, equations and complex tables.
